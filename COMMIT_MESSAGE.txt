Add the Scanner Module: scan-to-print, scan-to-email, scan-to-Wi-Fi-download

Implements roadmap-planning.txt Phase 6 and objectives-doc items 6-8 end to
end. Builds on the intake infrastructure from SESSION_MANAGER_SESSION_SUMMARY.md
and WIFI_EMAIL_END_TO_END_SESSION_SUMMARY.md, reusing the same SessionManager/
OTP/QR pattern proven there for Wi-Fi and email intake, run in reverse for scan
output. Replaces the old screens/scanner/* stub (fake scan, dev-bypass into
test_pdfs/) with a real flatbed capture pipeline.

- Hardware abstraction (`SSP/managers/scanner.py`, `scanner_manager.py`,
  `scanner_thread.py`): `SaneAirscanScanner` shells out to `scanimage -d
  <device> --format=png --resolution <dpi>` (no python-sane binding, mirroring
  how `printer_thread.py` shells to `lp`/`lpstat`), mapping
  `FileNotFoundError`/`TimeoutExpired`/`CalledProcessError`/empty output to one
  `ScannerError`. Flatbed only, one page per call, no ADF flags. Device string
  is operator-set via `.env` (from `scanimage -L` on the kiosk), not
  auto-discovered, since eSCL indices aren't stable across reboots.
  `SimScanner` seeds canned PNGs via `fitz` and round-robins fresh copies per
  call. `ScannerManager` (pure Python, no PyQt) owns page accumulation,
  `rescan_last()`, `cancel()`, and `finish()` (composes pages into one PDF via
  fitz). `ScannerThread` is a generic `QThread` wrapper for any bound
  `ScannerManager` method rather than one subclass per operation.

- Capture UI and photocopy routing (`SSP/screens/scanner/*` rewrite,
  `SSP/screens/scan_destination/`): the scanner screen gets a page counter,
  thumbnail preview, and Scan/Rescan Last Page/Done/Cancel controls; a
  `_scan_completed` flag stops `on_leave()` from deleting a just-finished
  scan's files on the way to the next screen. `scan_destination` presents
  Print Now vs. Send via Wi-Fi: Print Now hands the composed PDF to
  `printing_options_screen.set_pdf_data(pdf_data, selected_pages, "scanner")`
  unchanged — confirmed by reading `print_options/controller.py`/`model.py`
  that the existing pipeline only needs a path/filename and page list and
  re-derives everything else, so nothing downstream needed to change.

- Unified scan-to-email/Wi-Fi-download (`SSP/managers/adapters/scan_adapter.py`,
  `SSP/screens/scan_result/`, `SSP/webapp/routers/redeem.py` +
  `templates/redeem*.html`): rather than building an on-kiosk virtual keyboard
  (none exists anywhere in this codebase) to collect an email address, "Send
  via Wi-Fi" creates a `source="scan"` session (via a new `ScanAdapter`
  mirroring `wifi_adapter.py`) and shows a QR + OTP for a new phone-side
  redeem portal. `GET/POST /redeem` verifies via a new, additive
  `SessionManager.verify_otp_for_source_with_id("scan", otp)` and renders an
  actions page with hidden `session_id`/`otp` fields; `/redeem/download` and
  `/redeem/email` both re-verify via the existing `verify_otp()`, reusing its
  pre-existing "already verified" short-circuit instead of a new token
  system. `/redeem/email` builds the PDF attachment the same way
  `email_adapter.py` already does and sends via the existing `SmtpClient`.
  `webapp_thread.py`'s `wifi_portal_url()` was factored into a shared
  `_portal_url()` helper for the new `scan_redeem_portal_url()`.

- Config and wiring (`SSP/config.py`, `.env.example`, `SSP/main_app.py`,
  `SSP/.gitignore`): new `SCANNER_*`/`SIM_SCANNER_*`/`SCAN_UPLOAD_DIR`
  properties, all optionally defaulted per the existing pattern;
  `scan_destination`/`scan_result` added to `SCREEN_MAP` and the stacked
  widget; runtime upload/sim directories gitignored.

`make test` -> 115 passed (81 existing + 34 new: scanner manager, scan
adapter, redeem routes, plus 2 additive `verify_otp_for_source_with_id` cases).
`make lint` reports no new violations. Also verified live under SIM_MODE with
a scripted navigation smoke test through the real `PrintingSystemApp`: full
scan -> rescan -> Done -> scan_destination, both the Print Now path (correct
cost/page analysis in printing_options) and the Send via Wi-Fi path (session
creation and navigation to scan_result). Not yet exercised: the redeem portal
from an actual phone/browser, and any run against the real HP Smart Tank 580 —
both need the physical kiosk (see docs/session-summaries/
SCANNER_MODULE_SESSION_SUMMARY.md, Future considerations). See that file for
full details, a testing guide, and follow-up work.
