Let scan_destination select Print Now and Send via Wi-Fi together

UX refinement of the scan-to-print/Wi-Fi/email pipeline from
SCANNER_MODULE_SESSION_SUMMARY.md: turns the exclusive "Print Now vs. Send via
Wi-Fi" choice into a multi-select, adds a scanned-page preview neither
scan_destination nor scan_result had, and closes a copy gap that undersold the
Wi-Fi pathway. No changes to SessionManager, ScanAdapter, or the /redeem
webapp — a fuller split of Wi-Fi-download and email into separate kiosk
widgets was designed in full and then rejected: it forces that decision at the
kiosk instead of on the phone, removing the ability to change your mind once
you're looking at your device, for a mostly cosmetic benefit.

- Multi-select destinations (`SSP/screens/scan_destination/view.py`,
  `model.py`, `controller.py`): `ui.widgets.Card` fires its `clicked` signal
  unconditionally with no persisted state, and every other screen depends on
  that one-shot behavior, so rather than modify `Card` itself, added a local
  `DestinationOption(QFrame)` wrapper that owns a `Card` plus a `_selected`
  bool and emits `toggled(key, is_selected)` instead of acting immediately.
  Both destinations sit behind a single `Continue` button, disabled until at
  least one is selected. `ScanDestinationModel.confirm_selection(selected_keys)`
  replaces the old exclusive `send_via_wifi()`: if `send_wifi` was picked, the
  Wi-Fi/email session is created immediately as before; the controller then
  decides whether to also route through printing via a `wants_print` flag and
  a `pending_print` hand-off carried into scan_result.

- Page-thumbnail preview (`SSP/screens/scan_destination/thumbnail_thread.py`,
  new): neither screen showed the actual scanned pages, only a page-count
  label. Since `ScannerManager.finish()` deletes the per-page source images
  once composed into the final PDF, added `ThumbnailRenderThread`, mirroring
  `screens/file_browser/view.py`'s existing `PDFPreviewThread` pattern
  (`fitz.Page.get_pixmap()` -> `QImage` -> `QPixmap`) but kept local to this
  screen rather than imported across screen packages. Renders off the main
  thread into a horizontally-scrolling strip; reads whatever PDF
  `ScannerManager.finish()` produced, so SIM_MODE's placeholder pages show up
  automatically with no separate simulation path.

- Conditional "Continue to Print" (`SSP/screens/scan_result/model.py`,
  `view.py`, `controller.py`): when both destinations are selected together,
  the Wi-Fi session is created first, so `scan_result`'s Done button now
  relabels to "Continue to Print" when a `pending_print` hand-off is present
  (`has_pending_print()`), handing the stashed `pdf_data`/`selected_pages` to
  `printing_options_screen.set_pdf_data()` instead of returning to homepage.
  This also shifted temp-PDF cleanup: `scan_destination` only deletes it
  immediately when there's no pending print, since `printing_options` still
  needs the file otherwise.

- Copy: naming both pathways and dropping phone-only language
  (`scan_destination/view.py`, `scan_result/view.py`): the "Send via Wi-Fi"
  card's bold title named only one of its two capabilities — retitled to
  "Download or Email" so both are visible without reading the smaller
  description. Every mention of "your phone" (card description, scan_result's
  title and guide text) reworded to "your own device — phone, tablet, or
  laptop" throughout both screens.

`make test` -> 115 passed (no new tests — SessionManager/ScanAdapter/redeem
router are untouched, so there's no new unit-testable surface). `make lint`
reports no new violations on any touched file. Also verified: every touched
file compiles cleanly, and a SIM_MODE boot of the full PrintingSystemApp
constructed all screens without raising. The user manually confirmed via
`make run-sim` that toggling both destinations together and pressing Continue
routes correctly end to end. See
docs/session-summaries/SCAN_DESTINATION_MULTISELECT_AND_PREVIEW_SESSION_SUMMARY.md
for full details, a testing guide, and follow-up work.
