Wire up zoom controls and fix selection UI in the print/scan file editor

Polish pass on file_browser, the page-selection editor shared by both
the print flow and the scan flow (scanner routes into it via
set_source("scanner")). Not tied to a roadmap-planning.txt phase —
this is UI/UX polish, built on top of file_browser's own Phase B
theming rewrite (Header/BackButton/theme tokens, DragScrollArea wired
in, the #fffff CSS typo fixed) that arrived in the working tree
already uncommitted from a separate, not-yet-summarized prior session.
That rewrite is the exact item KIOSK_UI_REDESIGN_SESSION_SUMMARY.md's
follow-up list flagged as unstarted; this commit is not it and does
not re-describe it.

- Zoom controls (screens/file_browser/view.py, controller.py,
  pdf_preview_widget.py): the zoom backend (PDFPreviewWidget.zoomIn/
  zoomOut/resetZoom, controller._zoom_in/_zoom_out/_zoom_reset) already
  existed but had no UI — no button, and update_zoom_label() referenced
  a self.zoom_label that was never created, so it would have raised
  AttributeError the first time anything called it. Added +/-/Reset
  buttons and a live percentage label to single-page view, wired
  through new zoom_in_clicked/zoom_out_clicked/zoom_reset_clicked
  signals. Also fixed a real bug found while wiring it up:
  PDFPreviewWidget.paintEvent() computed zoom as a raw multiplier on
  the PDF's native (very high-DPI) pixel size instead of the
  fit-to-widget size, so the first zoom-in click would have jumped
  discontinuously instead of scaling smoothly from 100%.

- Selection outline & fill colors (screens/file_browser/view.py): the
  page-selection UI (grid thumbnail frames, both checkboxes, the
  preview container border, the selected-count label) all keyed off
  COLORS['success'], which is the literal same hex as COLORS['primary']
  — every primary button in the app. Added PAGE_OUTLINE_COLOR (grey)
  and PAGE_SELECTED_COLOR (near-black), scoped to file_browser only so
  the shared 'success' token (still used correctly elsewhere, e.g.
  status banners) wasn't touched. Also fixed a bug where a page's
  initial-render border ignored the checked constructor argument, and
  a follow-on bug where the checked-state frame used a 3px border vs.
  2px unchecked, visibly shrinking the thumbnail's content area on
  select — both states now share one border width.

- Checkmark icon (new assets/icons/checkbox-checked.svg,
  screens/file_browser/view.py): replaced a flat black-fill checked
  checkbox with a rounded-square + checkmark icon matching a
  user-supplied reference image, since QSS can't draw a checkmark path
  directly on QCheckBox::indicator. Wired via QSS image: url(...)
  through ui/icons.py's existing icon_path() helper. Verified by
  rasterizing the SVG through the project's own PyQt5 QSvgRenderer at
  both preview size and the actual 20x20 on-screen indicator size.

75 tests passing, no new failures; lint introduces no new violations.
