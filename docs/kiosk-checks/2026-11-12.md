# Kiosk checks, 2026-11-12

The second kiosk walkthrough, after [the 2026-11-11 one](README.md). It checks the changes
that haven't run on the kiosk yet, plus the few thesis test cases nobody has run. Follow it
top to bottom, and copy every command exactly as written.

**What's being checked.** None of these are merged. They're combined on one test branch,
`test/kiosk-checks-2026-11-12`, so the kiosk only has to switch to it once:

| PR | Change |
|---|---|
| #145 | A pickup code opens its Session again, typed or by QR. This is the fix for yesterday's failed 4.3. |
| #137 | Reports screen on Kiosk Admin |
| #138 | The Digital Copy fee moves into Settings, on both the touchscreen and the dashboard |
| #139 | Printer status on the dashboard's `/kiosk` |
| #140 | Every operator change is recorded (who, where, old and new value) |
| #141 | The data viewer shows the same columns and pages as the dashboard's `/logs` |
| #142 | Edit paper, coins and ink, and Collect cash, from the dashboard |
| #143 | Mark errors resolved, from both sides and from the PIN override |

The branch is built on today's `main`, which since yesterday's run also has print order and
several files per transaction (#121, #125–#127, tested in yesterday's Part 5 and now merged)
and #144 (the email reply is retried on the next poll if sending fails; merged after
yesterday's run). 4.3 step 4 covers #144's normal path.

Part 5 then runs the thesis test cases still marked "Not yet run" that take only minutes.
Each check is tagged with its test-case ID from the thesis appendix (for example `COD-03`),
so the results go straight into it.

**Time:** about 2¼ hours. Part 4 is about 1½ hours, Part 5 about 35 minutes.

**If something goes wrong:** don't fix the code. Take a photo of the screen, copy the last 50
lines of the log (`tail -n 50 ~/SSP-Plus/SSP/logs/app.log`), carry on with the next check,
and tell Riley. A failed check is a useful result. If the app won't start at all, put the
kiosk back on `main` (Part 6, step 1).

## Part 4. Check the changes

Write each result in the table in Part 7 as you go.

### 4.1 Kiosk Admin's new layout (#137, #138, #143). `OPS-13`

1. Tap **Admin** and enter the PIN. Check the whole screen fits the panel, and take a photo.
2. Check:
   - the top group is called **Paper** and has **no Digital Copy fee** stepper any more;
   - the bottom row has **Reports**, **Settings** and **View Data Logs**;
   - the **Device Status** row reads `Printer: …`, `QR Reader: …` and a new
     `Errors: N unresolved` (or `None unresolved`). Write N down.

### 4.2 Digital Copy fee in Settings (#138). `OPS-14`

1. In Kiosk Admin tap **Settings**. There are now **8** settings; the last is **Digital Copy
   fee** (₱). Write down its value (probably 5).
2. Set it to `7` and **Save**. Then `101` and **Save**: it should be refused with a message (the
   range is ₱0–100). Leave Settings and open it again: the fee still reads 7.
3. Go to the homepage, tap **Scanner**, put one sheet on the scanner glass and scan it. On the
   screen where you choose print or Digital Copy, the Digital Copy should say **₱7**. Tap
   **Back** until you're on the homepage; don't pay.
4. Set the fee back to the value you wrote down and **Save**.

### 4.3 Pickup codes work more than once (#145). `COD-03`, `COD-06`, `COD-14`

This is yesterday's failed 4.3. A code should open its files as many times as you like for 12
hours, typed or by QR.

1. **Typed, twice.** On the phone, join **AIO-SPARK**. On the kiosk tap **WiFi**, open the
   address it shows on the phone, and upload `A-color-1-page.pdf`. Write down the 6-digit code.
   On the WiFi screen, type the code and **Send**: the file list opens. Tap **Back** until
   you're at the homepage. Tap **WiFi** and type the same code again: it should **open
   again**. Do it a third time.
2. **By QR, twice.** The phone still shows the QR for that upload. Hold it up to the kiosk's
   QR reader on the homepage: the file list opens. Go back to the homepage, wait 5 seconds,
   and show the same QR again: it should **open again**.
3. **A wrong code still fails.** On the WiFi screen type `000000` and Send, once: it says
   **Incorrect or expired code**.
4. **A real code on the wrong screen never locks** (needs internet). Tap **Email**, send one
   email with `B-bw-3-pages.pdf` to the address shown, with the subject word. When the reply
   comes, type its code on the **Email** screen: B opens. Go back, then type the **same Email
   code on the WiFi screen five times**. It says **Incorrect or expired code** each time, but
   should **never lock** (no countdown, keypad stays on).

   With no internet, skip step 4 and write "not tested, no internet". Note how long the
   reply took: #144 changed when the reply is sent.

### 4.4 Data viewer: same columns as `/logs`, and the Admin Actions tab (#141, #140). `OPS-16`, `OPS-17`

1. Kiosk Admin → **View Data Logs**. Take a photo of each tab.
2. **Transactions** tab columns, in order: ID, Time, File, Source, Pages, Copies, Colour,
   Cost, Paid, Change, Status. The newest transaction is at the top. Under the table,
   **Newer / Page 1 of N / Older**: tap **Older**, then **Newer**.
3. **Error Log** tab has a **Resolved** column, and the same Newer/Older row.
4. **Admin Actions** tab: the two Digital Copy fee changes from 4.2 are listed, newest first,
   each with who = `kiosk`, where = `touchscreen`, and the old and new value (5 → 7, 7 → 5).
   The refused `101` is **not** listed.

### 4.5 Resolving an error with the PIN override (#143). `OPS-20`

The kiosk stops for customers when a tank is marked empty (0%). That shows an error screen
and writes an error row, which the PIN override should now mark resolved.

1. In Kiosk Admin, write down the `Errors:` count. Tap the **Cyan** field, type `0`, and
   tap **Update**. Tap **Back to Main Screen**. The kiosk should show the error screen with
   **An ink tank is empty** and an **Admin Override** button.
2. Tap **Admin Override** and enter the PIN. Kiosk Admin opens.
3. Set **Cyan** back to the value you wrote down in Part 2 and tap **Update**.
4. **Errors:** in Device Status should be the same number as in step 1 (the new error was
   written, then resolved).
5. **View Data Logs → Error Log**: the newest row is the ink error, with **Resolved = yes**.
   **Admin Actions**: rows for Cyan → 0, the error marked resolved, and Cyan back.
6. **Mark selected resolved:** on the Error Log tab, tap an older row that isn't resolved. The
   **Mark selected resolved** button turns on. Tap it: that row's Resolved becomes yes, and
   Kiosk Admin's `Errors:` count goes down by one. Write down which row (time and type).

### 4.6 The Reports screen (#137). `OPS-13`

1. Kiosk Admin → **Reports**. Check it fits the panel; take a photo.
2. Tap each range: **Today**, **This week**, **This month**, **All time**. For **All time**,
   write down: the revenue and number of transactions per Source (USB, Wi-Fi, Email,
   Scanner), Change dispensed, Voucher value issued, Vouchers Applied, Outstanding Voucher
   liability, and the newest collection listed (yesterday's test collection should be there).
3. You'll compare these with the dashboard in 4.7, step 9.

### 4.7 The Admin Dashboard: printer status, edits, resolving, and the audit (#139, #142, #143, #140). `OPS-15`, `OPS-16`, `OPS-18`, `OPS-19`, `OPS-20`

1. **Make a read-only account** for the operator check (pick a name and password):

   ```bash
   cd ~/SSP-Plus
   PYTHONPATH=SSP .venv/bin/python -m admin_dashboard.cli create-account --username test-operator --password '<a password>' --role operator
   ```

2. **Start the dashboard** in its own SSH window and leave it open:

   ```bash
   cd ~/SSP-Plus && make run-admin-dashboard
   ```

3. On the laptop, open **http://aio-spark-kiosk.local:8100** and log in with your **admin**
   account from yesterday. (you can use "me" for the username and "pass1234" for the password - not the bot)
4. **Printer status (#139).** `/kiosk` shows **Printer:** with the same words as Kiosk
   Admin's Printer line, in green, followed by **as of** a time within the last minute or so.
   Take a screenshot. Now **open the printer's front door** (or pull the paper tray). Wait 2
   minutes, then refresh `/kiosk`: it should show the same warning Kiosk Admin shows (for
   example *Door open*), in orange or red, with a newer "as of" time. Close the door, wait 2
   minutes, refresh: back to green.
5. **Edits from the dashboard (#142).** The touchscreen only rereads values when you open
   Kiosk Admin, so for each edit: make it on the dashboard, then open Kiosk Admin on the
   touchscreen to check, then go back to the idle screen.
   1. **Paper:** set it to your Part 2 number **minus 1**, tap **Set**. Kiosk Admin shows the
      new number. Then tap **Refill to 100**: Kiosk Admin shows 100. Then **Set** it back to
      your Part 2 number.
   2. **Coins:** set ₱1 and ₱5 to your Part 2 numbers **plus 1** each, **Set**. Check on
      Kiosk Admin. Then set them back.
   3. **Ink:** set Magenta to its Part 2 value minus 1, **Set**. Check on Kiosk Admin. Set it
      back. (Don't use **Refill All** for ink: it would replace the real estimates with 100%.)
   4. **Out of range:** set paper to `-5` (or ink to `150`) and **Set**. It should be refused
      with a message, and nothing changes.
6. **Collect cash from the dashboard (#142).** This records another test collection and sets
   every count to 0.
   1. Tap **Collect cash…**. A confirm box lists each coin and bill with its count and a
      total; it should match what Kiosk Admin's own Collect cash dialog would show. Take a
      screenshot. Tap **OK**.
   2. Open Kiosk Admin: all coin counts are 0. `/accounting` lists the collection.
   3. **Put the coin counts back** from the dashboard: set ₱1 and ₱5 to your Part 2 numbers.
      Kiosk Admin shows them, and the idle screen's low-change banner goes away.
7. **Mark resolved on the dashboard (#143).** `/kiosk` lists unresolved errors, each with a
   **Mark resolved** button. Tap one. It disappears from the list, the count in the heading
   goes down by one, and Kiosk Admin's `Errors:` count (reopen it) goes down too. On `/logs`,
   the Error log shows it as resolved.
8. **The audit on `/logs` (#140).** Scroll to **Admin actions**. Check that:
   - every dashboard edit from steps 5–7 is there, with **your username** and the laptop's
     address (something like `192.168.137.1`);
   - the touchscreen changes from 4.2 and 4.5 are there too, as `kiosk` / `touchscreen`;
   - the refused out-of-range edit from 5.4 is **not** there.

   Take a screenshot. Open the touchscreen's data viewer → **Admin Actions**: the same rows.
9. **Reports vs `/accounting` (#137).** On `/accounting`, pick **all**. The per-Source
   revenue and counts, change, Voucher figures and collections should equal what you wrote
   down in 4.6, plus the collection from step 6. Check one more range (**today**) against the
   Reports screen. Take a screenshot of each.
10. **Read-only operator (#142, #143).** In the private browser window, log in as
    `test-operator`. `/kiosk` shows every value but **no** Set, Refill, Collect cash or Mark
    resolved buttons. `/settings` shows values but can't save. Take a screenshot.
11. **Remove the test account**, and stop the dashboard (Ctrl+C in its window):

    ```bash
    cd ~/SSP-Plus && .venv/bin/python -c "
    import sqlite3; c = sqlite3.connect('SSP/database/ssp_database.db')
    c.execute(\"DELETE FROM users WHERE username='test-operator'\"); c.commit(); print('removed')"
    ```

## Part 5. Thesis test cases not yet run

These aren't new code. They're the cases still marked "Not yet run" in the thesis appendix
that take only a few minutes.

### 5.1 A password-protected PDF from USB. `USB-03` (second half)

On the homepage tap **USB**, insert the drive, and tap `E-password-protected.pdf` in the file
list. Expected: it's marked as **can't be opened**, the reason shows where the preview would
be, and **Continue** stays grey. Take a photo.

### 5.2 Time from choosing a file to its price. `OPT-06`

With the USB drive still in, use the stopwatch. For each of `A-color-1-page.pdf`,
`F-color-10-pages.pdf` and `G-color-50-pages.pdf`: select the file, tap **Continue**, choose
**Color**, and start the stopwatch as you tap Color (or as the print options screen opens if
Color is already chosen). Stop it when the price appears. Write down the three times. Don't
pay; tap Back.

### 5.3 21 PDFs in one upload. `WIF-13`

On the phone, on the WiFi upload page, choose all 21 files from `batch-of-21/`. Expected:
refused with **Too many files (max 20)**. Then choose 20 of them (leave out `batch-21.pdf`):
accepted as one code. Type the code on the kiosk: the file list shows 20 files. Tick three
of them and check nothing is cut off at the **right edge** of the screen (the Deselect All
button and the page previews): a render on a laptop came out 20 pixels too wide. Take photos.

### 5.4 Upload time, 1 MB and 24 MB. `WIF-14`

1. Make the two files on the kiosk and copy them to the laptop:

   ```bash
   cd ~/SSP-Plus && .venv/bin/python ~/make_test_pdfs.py --big
   ```

   In the laptop's PowerShell:

   ```powershell
   scp group-c@aio-spark-kiosk.local:H-about-1MB.pdf $HOME\Desktop\
   scp group-c@aio-spark-kiosk.local:I-about-24MB.pdf $HOME\Desktop\
   ```

   Get both onto the phone any way you like (a cable, Google Drive, Messenger).
2. On the phone, on **AIO-SPARK**, upload `H-about-1MB.pdf`. Start the stopwatch as you tap
   **Upload** and stop it when the code shows. Then the same for `I-about-24MB.pdf`. Write
   down both times and the phone's model.
3. Clean up: `rm ~/H-about-1MB.pdf ~/I-about-24MB.pdf`

### 5.5 Opening the scanner lid mid-scan. `SCN-11`

Put a sheet on the scanner, tap **Scanner** and start a scan. While it's scanning, lift the
lid. Expected: the scan ends with an error or a partial page, and the kiosk recovers (you can
go back, or scan again). Write down exactly what the screen said, and whether a second scan
works with the lid closed.

### 5.6 Five wrong admin PINs, then a restart. `OPS-02`. **Do this last**

This locks Kiosk Admin for 5 minutes and sends the operator an SMS.

1. Tap **Admin** and enter a wrong PIN five times. Expected: the keypad locks with a
   countdown from 5 minutes.
2. Restart the app while it's locked:

   ```bash
   systemctl --user restart ssp-kiosk
   ```

   Tap **Admin** again: still locked, still counting down.
3. Check the operator's phone got an SMS, and that an error row was written:

   ```bash
   cd ~/SSP-Plus && .venv/bin/python -c "
   import sqlite3; c = sqlite3.connect('SSP/database/ssp_database.db')
   print(c.execute('SELECT timestamp, error_type, error_message FROM error_log ORDER BY id DESC LIMIT 3').fetchall())"
   ```

4. Wait for the countdown to end; the right PIN works again.
